Architecture & Tokenomics Insights:
How Caching Works

Why Cached Tokens Save Money

📖 How Caching Works in ARIA (Wiki) 📘 Token Optimization & Saving Process

ARIA keeps the stable instruction prefix, template vocabulary, and policy context reusable. The model reuses that prefix across calls instead of processing identical input tokens again.

Stable template context→Provider prefix cache→Only new evidence costs input tokens
Cached tokens are still measured for traceability, but the dashboard estimates their cost separately from uncached input tokens.
Cost & Accuracy Governance

How ARIA Guarantees High Accuracy While Remaining Cost-Efficient

Step 1

⚡ Micro-Tier First (`aria-text-mini`)

Extracts fields using high-throughput, low-latency micro models ($0.15/1M). Computes a visual & structural confidence score for every extracted field.

Step 2

🎯 Dynamic Fallback to Vision (`aria-vision`)

If any field's extraction confidence falls below 80%, ARIA automatically escalates that specific document section to multimodal aria-vision (GPT-4o).

Step 3

🛡️ 100% Deterministic Policy Validation

Extracted values undergo strict code-level rule evaluation (unit normalization, alias mapping, authority lists) to ensure zero hallucinated risk verdicts.

Cost Reduction Guide

Token Optimization & Saving Strategies

⚡

Mini model tier routing

Route 95% of standard document text extractions to aria-text-mini ($0.15/1M tokens) instead of full gpt-4o ($2.50/1M). Fall back to vision models only when visual OCR confidence is <80%.

94% savings on text extraction
🔄

Prefix prompt caching

Structure static system instructions, field schemas, and inspection policy rules at the very front of the prompt. Providers auto-cache prefixes >1024 tokens for a 50% input discount.

50% discount on input prefix
🎯

Strict JSON schema responses

Use JSON response format mode to eliminate conversational preamble, reasoning text, and verbose markdown, cutting completion token overhead drastically.

65% reduction in output tokens
📦

Document hash deduplication

Compute SHA-256 hashes of incoming document pages before submission. Identical pages across multi-page evidence bundles are skipped, preventing duplicate extraction calls.

100% bypass on duplicate pages
